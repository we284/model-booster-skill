# 评审与决策模式增强流程

适用于两类任务，先分流：

- **A 方案评审**：对象是别人（或自己早先）给出的方案、代码设计、文档、商业计划，要的是"哪里有问题、有多严重、怎么改"。
- **B 决策建议**：对象是若干可选路径，要的是"选哪个、为什么、什么条件下会反转"。

两类共用阶段 0-2，从阶段 3 起分开。

## 目录

1. 阶段 0：界定对象与判定标准
2. 阶段 1：枚举选项（B）或拆解主张（A）
3. 阶段 2：建立评价维度并定权重
4. 阶段 3A：方案评审——分级问题清单
5. 阶段 3B：决策建议——逐项评估与敏感性检验
6. 阶段 4：结论形态（强制格式）
7. 攻击测试模板
8. 高频缺陷清单

## 阶段 0：界定对象与判定标准

先固定三件事，缺失且无法从上下文推断时就问：

1. **判定标准**：这次评审/决策"什么算好"，必须在看细节之前定下。标准来自用户目标，不是你偏好。
2. **约束与不可接受后果**：硬约束（预算、期限、合规、兼容性）先列，违反即淘汰，不进打分。
3. **基线**：不做任何改变会怎样。没有基线的决策建议是不完整的——"维持现状"必须作为选项之一参与比较。

方案评审还要确定**评审视角**：技术可行性、业务价值、成本、风险、可维护性，用户只说"帮我看看"时，覆盖全部视角但按风险排序输出。

**前提校验**：评审对象里对现状的描述（"线上经常超时""竞品都做了 X"）和决策输入里的事实（市场规模、成本数字）先过台账；被方案当依据用的关键数据是最优先核实项——依据错了，方案的对错无从谈起。

## 阶段 1：枚举选项（B）或拆解主张（A）

**B 决策**：

- 至少三个选项：用户给的选项 + **维持现状** + **最小可行改动**。二选一通常是伪二选一。
- 每个选项标出：核心假设、前置条件、不可逆程度、退出成本。
- 未知信息单独列出，按台账标 U（"未验证"），不许用假设填空后当事实。

**A 评审**：把方案拆成可独立判断的主张，每条写成一句可判真伪的话。

```text
主张：引入消息队列可将峰值写入延迟降到 200ms 以内
隐含前提：已有可运维的 MQ 集群；延迟瓶颈在写入侧
可核查性：需要压测数据；检索后仍无数据 → 标 U
```

拆不出主张、只剩形容词的段落（"架构先进、扩展性强"），本身就是一条 P1 问题：不可验证。

## 阶段 2：建立评价维度并定权重

1. 维度 4-6 个为宜，过多会互相稀释。常用：目标达成度、成本、风险、可逆性、实施复杂度、长期维护。
2. 权重先定，再看各选项得分——顺序颠倒就是事后合理化。
3. 每个维度写清**打分依据**（可量化的量化，不可量化的给判定门槛），否则打分是主观装饰。
4. 维度之间尽量不重叠；发现两个维度高度相关时合并。

## 阶段 3A：方案评审——分级问题清单

输出按严重度分级，每条必须三件套：**位置 + 问题 + 修法**。没有修法的批评不算完成。

| 级别 | 含义 | 处理要求 |
|---|---|---|
| P0 阻断 | 方案不成立或会造成实质损失（事实错误、违反硬约束、安全漏洞、逻辑不成立） | 必须改，不改不能推进 |
| P1 重要 | 成立但有明显缺陷：遗漏关键场景、论证缺证据、成本被低估、维护成本高 | 应改，给出改法 |
| P2 建议 | 表达与优化：结构、术语、冗余、可读性 | 可选 |

评审硬性要求：

- **先给整体判断，再给清单**：一句话说清"能用 / 需修改后能用 / 不能用"，再展开。
- **先找事实错误，再谈观点分歧**。事实错误优先于风格偏好。
- **区分"我不同意"与"这是错的"**：前者标观点分歧并说明你的依据，后者必须给反例或证据。
- **正面确认也要点名**：方案中确实做对的关键取舍要指出，否则用户不知道哪部分别动。
- 不许只挑容易挑的（错别字、格式）而回避核心论证。

## 阶段 3B：决策建议——逐项评估与敏感性检验

1. 按阶段 2 的维度逐项打分，每格附一句依据；已查证仍无依据的格子标 U，不许凭印象填。
2. **敏感性检验（必做）**：把权重向第二重要维度倾斜、把 U 类信息取悲观值，看推荐是否翻转。翻转了就说明结论不稳，必须在结论里写明"若 X 成立则改选 Y"。
3. **风险对称性检查**：各选项的下行风险是否可比？不可逆选项要额外加"退出成本"一栏。
4. **成本完整性**：迁移成本、学习成本、机会成本、后续维护成本，常被漏掉的是后两项。
5. 给出推荐排序，不只给第一名；第二名在什么条件下胜出要写明。

## 阶段 4：结论形态（强制格式）

```text
结论：推荐 X
依据：维度1（证据）> 维度2（证据）> 维度3（证据）
适用条件：在 A、B 成立时成立
反转条件：若 C 出现或 D 被证伪，改选 Y，因为……
复审触发：到 X 时点或出现 Y 信号时重新评估（决策有有效期，不是一锤定音）
已排除项及原因：Z 因违反硬约束/成本超预算被淘汰
未验证事项：XXX（影响程度：高/中/低）
下一步最小验证：用最小成本先验掉最高风险假设，具体动作是……
```

评审任务的结论形态：`整体判断 + P0 数量 + 最该先改的三件事 + 改完后的预期状态`。

## 攻击测试模板

评审与决策的初稿最容易犯"结论正确但理由空洞"或"漏掉整整一类选项"。逐一跑：

1. **反方最强论点**：站在对立面，写出反对你结论的最强理由（不是最容易被驳倒的那个），再正面回应。回应不了就改结论。
2. **最挑剔评审三问**：这个结论的最坏后果是什么？依据里哪一条最经不起推敲？如果预算/时间减半，结论还成立吗？
3. **前提失效测试**：把每条关键假设单独设为假，逐一推演结论是否崩。崩的那条就是必须最先验证的。
4. **遗漏选项测试**：除现有选项外，是否存在"都不做""拆开做""先做一半"这类被忽略的第三、第四选项？
5. **证据溯源测试**：结论里的每个数字、每条"业界普遍""用户反馈"，能否指到具体来源？指不到就降级或删除。
6. **一致性测试**：评审意见之间有无互相矛盾（一边要求加缓存一边要求降内存）？决策打分是否与自己定的权重一致？

六项里至少跑三项，且第 1、5 项必跑。跑完后按 SKILL.md §6 第 3 步执行批判：先过 critique-rubrics.md 第 2 节通用清单，再过第 6 节评审与决策清单，每轮修订完用第 7 节量表定级。

## 高频缺陷清单

- **伪二选一**：把连续可调的方案做成 A/B 对立，忽略折中与分阶段。
- **锚定**：先看到某个选项就围绕它找理由，权重事后调整。
- **沉没成本**：用已投入的时间、资金、人力论证继续，而它不影响未来的收益与成本对比。
- **只看显性成本**：漏机会成本、迁移成本、组织协调成本、长期维护成本。
- **以偏好代标准**：用"我觉得更优雅"代替目标达成度，且不说明这是偏好。
- **给结论不给条件**：只写"建议选 A"，不写什么情况下 A 会变成坏选择。
- **决策无有效期**：不写复审触发点，把一次结论当成永久结论。
- **把不确定当确定**：给未验证的收益打高分而不标 U。
- **评审只挑表面**：抓格式与措辞，放过核心假设不成立。
- **无条件正面**：为了不冒犯而模糊结论，两边都说好——这是评审失职。
- **过度批评**：把 P2 问题写成 P0，导致用户无法分辨真正该改的。
- **忽略基线**：不提"什么都不做"的后果，把改变默认成必须。
